# .gitignore

## O que é?

O `.gitignore` é um arquivo de texto que informa ao Git **quais arquivos e pastas ele deve ignorar**. Tudo que estiver listado nele **não aparece** no `git status` e **não é adicionado** por engano em commits.

É muito usado para excluir arquivos que não pertencem ao projeto, como dependências, arquivos temporários e segredos.

## Para que serve?

- Evitar commitar **dependências** (ex.: `node_modules/`).
- Ignorar **arquivos gerados** (ex.: `dist/`, `build/`, `*.log`).
- Proteger **segredos** (ex.: `.env`, chaves).
- Ignorar configurações **locais** do editor (ex.: `.vscode/`).

## Como criar

Basta criar um arquivo chamado `.gitignore` na **raiz** do repositório:

```bash
touch .gitignore
```

E adicionar os padrões, um por linha:

```
# Dependências
node_modules/
vendor/

# Arquivos gerados
dist/
build/
*.log

# Segredos
.env
*.key

# Sistema / editor
.DS_Store
Thumbs.db
.vscode/
```

## Padrões (patterns)

| Padrão | Significado |
| --- | --- |
| `arquivo.txt` | Ignora o arquivo em qualquer pasta |
| `*.log` | Ignora todos os arquivos com extensão `.log` |
| `pasta/` | Ignora a pasta inteira |
| `/arquivo.txt` | Ignora apenas na raiz do repositório |
| `**/temp` | Ignora `temp` em qualquer nível |
| `doc/*.txt` | Ignora `.txt` dentro de `doc/` (um nível) |
| `!importante.log` | **Exceção**: não ignora esse arquivo |
| `# comentário` | Linha de comentário |
| linha vazia | Ignorada |

## Exemplo de exceção

```
*.log
!importante.log
```

- Ignora todos os `.log`, **exceto** `importante.log`.

## Observações importantes

- O `.gitignore` **não afeta arquivos já rastreados** pelo Git. Para passar a ignorar um arquivo que já foi commitado, remova-o do rastreamento:

```bash
git rm --cached arquivo.txt
```

- A ordem importa: regras mais específicas e com `!` podem sobrescrever anteriores.
- Padrões terminados em `/` indicam **diretórios**.

## Outros locais de ignore

| Arquivo | Escopo |
| --- | --- |
| `.gitignore` | Repositório (versionado e compartilhado) |
| `.git/info/exclude` | Apenas o seu repositório local (não versionado) |
| `~/.config/git/ignore` | Global, para todos os seus repositórios |

Configurar o ignore global:

```bash
git config --global core.excludesfile ~/.gitignore_global
```

## Boas práticas

- Crie o `.gitignore` **no início** do projeto.
- **Commit o `.gitignore`** para que a equipe use as mesmas regras.
- Nunca confie só no ignore para segredos: mantenha chaves fora do repositório.
- Use modelos prontos por linguagem quando precisar (ex.: GitHub `gitignore` templates).

## Erros comuns

- **Achar que o `.gitignore` afeta arquivos já rastreados**: é preciso `git rm --cached`.
- **Esquecer de commitar o `.gitignore`**.
- **Usar o `.gitignore` para esconder segredos já commitados** (o histórico mantém).
- **Escrever o padrão errado** (ex.: `foo` ignora arquivo e pasta em qualquer nível).
- **Criar regras que ignoram arquivos necessários** por engano.

## Casos de uso

| Situação | Padrão |
| --- | --- |
| Ignorar dependências | `node_modules/` |
| Ignorar arquivos gerados | `dist/`, `*.log` |
| Ignorar segredos | `.env` |
| Ignorar arquivos do sistema/editor | `.DS_Store`, `.vscode/` |
| Abrir uma exceção | `!importante.log` |
